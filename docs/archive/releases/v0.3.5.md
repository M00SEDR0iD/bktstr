# v0.3.5 release archive

## Release identity

Release `v0.3.5` was tagged at commit `add435d`. A roadmap-only documentation commit, `219dc71`, was deployed after the tag. The tag was not moved: published release identities are immutable, so later documentation remains separate from the tagged release.

The post-release direction is recorded in the [standalone web application roadmap](../../roadmap/standalone-web-app.md).

## Frozen production acceptance

The accepted NVDA research baseline produced 7 trades, 6 wins, 1 loss, `$42.604714` total P&L, and `$6.086388` expected P&L per trade. Acceptance also required exact trading-output equality across two identical runs and second-run derived-cache hits for intraday, regime, and sentiment data.

The retained production acceptance command is:

```bash
python scripts/production_acceptance.py --base-url https://bktstr-production.up.railway.app
```

## Preserved release checks

The v0.3.5 checklist required work on a feature branch created from the current production `main`, followed by committing the feature branch and pushing it to GitHub, a passing **BKTSTR CI** workflow, and a merge to `main` only after CI was green. Local validation comprised:

```bash
python -m pytest -q
python -m compileall -q bktstr bktstr_cache integration scripts benchmarks tests
python benchmarks/benchmark_cache.py
```

The benchmark had to demonstrate a cold miss followed by a warm hit with one compute call. Repository hygiene used this retained `git ls-files` check:

```bash
git ls-files | grep -E '(^|/)(__pycache__|\.pytest_cache)(/|$)|\.py[co]$' || true
```

Any generated Python artifacts reported by that command had to be removed from Git before the release commit.

After merge, the checklist required confirmation that Railway deployed the new `main` commit. `/health` had to report `version=0.3.5` and a recorded `git_commit`; `/api/v1/capabilities` had to expose the v0.3.5 release, formula, and cache metadata. The production acceptance command above then verified the frozen baseline, exact repeat-run trading output, and warm derived-cache behavior before tagging the accepted commit as `v0.3.5`.
